部署方案 · 网站轨与实验轨独立运行

一、结论先行

能，且建议双轨物理隔离。 网站轨与实验轨的共同依赖只有「titan007 数据源 + PushPlus 微信推送」，彼此不需要对方的数据，因此可以完全独立部署、独立重启、独立故障。

二、两种架构

架构 A · 单机双隔离（推荐起步）

同一台服务器，目录/进程/任务三重隔离：

C:\jingcai\            ← 网站轨（现有，勿动）
   server.js           端口 80，开机自启（任务计划 JingcaiWeb）
   index.js  dist\  www\  snapshots\

C:\jingcai-exp\        ← 实验轨（新增，完全独立）
   rd\                  选票/判卷/校准脚本
   实验数据台账.md       只追加
   实验档案-全中假说.md   方法档
   logs\                每次运行日志
   out.txt              推送稿
  • 任务计划：JingcaiWeb（网站，AtStartup）+ JingcaiExp（实验，每日 12:10/21:10）
  • 端口：网站独占 80；实验不监听任何端口
  • 数据：实验只写 C:\jingcai-exp\，绝不触碰 C:\jingcai\
  • 隔离度：进程级（实验脚本崩溃/死循环不影响网站 Node 进程）

架构 B · 双机完全独立（有第二台服务器时）

  • 服务器 1（现有 ECS）：网站轨，维持现状
  • 服务器 2（新）：实验轨，仅需 Node + 出站网络
  • 优点：物理隔离，网站流量与实验计算零干扰；实验可随意重启/回滚
  • 代价：多一台机器成本；两套部署链路（但实验轨部署更简单——无公网端口、无域名/备案要求）

建议：先上架构 A 验证，若实验任务变重（如每日跑大样本回测）再拆到 B。实验轨最低配 1 核 2G 足够。

三、实验轨自动化设计（针对历史事故的硬约束）

历史事故（来自台账/日志，必须在服务器版根治）：

事故根因服务器版对策
值守多次未触发（runCount 卡住）依赖 ZCode 宿主调度改用 Windows 任务计划（OS 级，不依赖 agent 宿主）
9-3 推送含不存在场次脚本依赖手改 WATCH 数组的旧数据每次运行重新拉全量在售，禁用任何硬编码场次
并行会话覆盖 out.txt多进程同写实验轨单进程串行 + 文件锁，任务计划不允许并行实例
台账并发写冲突多 agent 同时编辑单进程追加写；写入前校验尾部行
PushPlus 999 防刷同标题同内容标题自动带时间戳

每日任务编排：

12:10  判卷档：拉昨日赛果 → 三层判卷（方向/总球桶/比分）→ 追加台账 → 推微信
21:10  选票档：拉在售全量 → 层1否决 → 层2筛选 → 组装 → 硬校验 → 推微信
周日 22:00  校准档：重跑 calib-*.js（T 分层/前二和/EV 稳健性）→ 报告 alpha 是否衰减

选票前硬校验（脚本内强制，失败即停）：

  1. 每腿开赛日期时间与在售页一致（防跨日漏打）
  2. 注数 = 2^(双选腿数)，金额与结构对账（防 8注16元错版）
  3. 否决闸门复核（P总5≥25% ∨ P净4≥20% 即剔除）
  4. 单腿复用 ≤2 张票
  5. 台账追加成功后才推送

关于"判断"：五层筛选、否决、pm 前二组装可完全脚本化（确定性、可复现、零事故）。私货形态偏移若需 LLM 判断，则服务器侧调 API 或保留本机 agent 半自动——建议先跑纯规则版，把判断留给人工复核。

四、部署步骤（新服务器，约 20 分钟）

  1. 装 Node：winget install OpenJS.NodeJS.LTS 或官网 zip（≥ v20）
  2. 建目录：C:\jingcai-exp\，上传 rd/（脚本）、data/（历史矩阵）、两份实验 md
  3. 配置 token：从 index.js 读 PushPlus token（或写环境变量，勿硬编码进脚本）
  4. 注册任务：

```powershell

$a = New-ScheduledTaskAction -Execute 'C:\Program Files\nodejs\node.exe' -Argument 'C:\jingcai-exp\rd\daily.js' -WorkingDirectory 'C:\jingcai-exp'

$t1 = New-ScheduledTaskTrigger -Daily -At 12:10

$t2 = New-ScheduledTaskTrigger -Daily -At 21:10

Register-ScheduledTask -TaskName 'JingcaiExp' -Action $a -Trigger $t1,$t2 -User 'SYSTEM' -RunLevel Highest

```

⚠ 坑（历史记录）：-User 'SYSTEM' -RunLevel Highest 必加，否则 0x80070534

  1. Dry-run：node rd\daily.js --skip-push 验证抓取/筛选/写台账全链路
  2. 首次真实运行：手动触发一次，核对微信推送
  3. 上线：任务计划 Enable

服务器无需：公网端口、域名备案、HTTPS（实验轨只出站）

五、风险与注意

  1. 服务器上没有 LLM：纯规则脚本可跑；如需 agent 判断，需 API key + 出站额度
  2. 数据源限频：titan007 限并发 5、澳客 300ms 间隔——服务器版需保留节流（历史封 IP 事故）
  3. 凭证管理：阿里云 AccessKey 轮换（历史两次明文泄漏）；微信 token 建议环境变量
  4. 台账单一写者：服务器接管后，本机 agent 改走"读服务器台账 + 只提建议"，避免双写
  5. 回滚：实验轨脚本改动前先备份到 backup\，与网站轨备份链同规矩
