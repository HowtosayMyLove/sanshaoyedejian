判断复刻手册 — 接手 agent 的行为级复刻指南

目的：让接手 agent 在本项目上做出与 8-27/8-28 会话中 AI 一致质量的判断，而不只是机械执行规则。
原理：知识在 CONTEXT/REPORT，流程在实验档案 §三/§八，本文件补最后一块——判断模式（每条都来自真实案例，标注来源）。
用法：每次做选票/判卷/回复用户前，过一遍本手册对应条目。

一、等价对处理（免费二选一）

场景：两个比分市场定价差 <1 个百分点（如巴萨 3:0/2:0 同为 10.8%，安德莱 2:1/2:0 同为 11.1%）。

规则：

  1. 先问：我的 T/区间判断倾向哪边？→ 选自洽的一侧（巴萨 T=3.70 → 取 3:0）
  2. 选定后不再摇摆，备选写进双选区而不是改首选
  3. 绝不因为"叙事感觉"在等价对之间换边

案例：巴萨取 3:0 ✅（2:0 也中，双选覆盖）；安德莱 2:1/2:0 双选漏了实际的 3:0 —— 见 §二。

二、叙事禁令（第二选区怎么选）

场景：双选的第二比分，pm 排序第三的格子（8.6%）与"叙事上说得通"的格子竞争时。

规则：第二选区永远取 pm 排序的下一顺位，禁止用"客队有偷球实力""主队要证明自己"这类叙事替代数据。

案例：8-28 安德莱场——我取 2:1/2:0，实际打出序列第三的 3:0。若当时按 pm 顺位补 3:0 则全中。教训已录入：叙事在等价对之外的位置 = 负价值。

延伸：若真想覆盖第三顺位，正确做法是三选（成本 +1 注），而不是用叙事换掉第二顺位。

三、验证反射（任何数字出口前）

规则：说出口的每一个百分比、金额、赔率，必须满足以下之一：

  1. 能指出数据来源（哪个文件哪张表哪次回测）
  2. 当场跑 rd\ 下对应脚本现算（mypick/blowout/review-days/totalbucket…）
  3. 明确标注"估算/近似"

案例：期 0 判卷我算出 640.25 元被用户一眼纠错（同场双选重复计注，正确 389 元）——金额必须逐注核对"每场只兑实际命中注"。此错误模式已写进判卷口径。

案例 2（2026-09-01，EV 双口径）：TG 线回测推送把三档组合"每场回收均值 4.85"错当单注 EV 写成 +385%——正确 EV 率=回收÷投入 3 注=+62%；同夜双选 EV 又漏算投入一半（每场 2 注 4 元写成 2 元，+65.8% 实为 -17.1%）。回测输出的"每场回收"与"每注 EV 率"是两个口径，出口前必除以注数/乘以投入。

案例 3（2026-09-01，回测样本纪律）：TG 线 94 场六天回测 +62% 经用户要求大样本检验后，5729 场证伪为 -37.6%（大球爆发周期假象）——六天样本只配有资格提出假说，+EV 结论必须过 1000+ 场跨月检验。

自检句式：出口前默念"这个数从哪来？除以注数了吗？过千场检验了吗？"

三点五、实盘认定反射（任何"已出票/已下单"表述前）

规则：用户没有亲口确认"已出票"，agent 选出的票一律记纸面；严禁在档案/推送里写"已出票""照单出票即可"这类替用户陈述事实的话。

案例：8-28 晚连续两轮误标"已出票"（16 元方案 + 期 1），用户 22:17 纠正"我一张也没打到"——全部降级纸面重录。agent 的输出止于建议，出票是用户的物理动作。

自检句式：这句话是在描述我的建议，还是在替用户陈述他做过的事？

三点六、注数反射（任何票面金额出口前）

规则：3串1 的注数 = 2^(双选腿数)。单+双+双 = 4 注 8 元；双+双+双 = 8 注 16 元。写票面时先算注数、再写金额，且金额必须与结构条款（≤8 元/张）对账。

案例：8-29 晚两版票面都写"3串1·4注8元"但腿型给了三个双选（=8注16元），用户抓出"你3个双选那不成了16块"。同场双选兑付教训（640→389）是同一族错误：金额计算不经过反射直接出口。

自检句式：注数=2^双选腿数，算出来了吗？总额对得上预算吗？

四、用户纠错协议（被指出错误时）

五步，顺序不可乱：

  1. 立即承认（"你说得对/我算错了"），不辩解不找补
  2. 当场重算/重验，给出正确值和差异原因
  3. 修正所有受影响文件（档案/memory/数据表）
  4. 补一条教训进流程（让同类错误不能再犯——期 0 金额案→判卷口径条款）
  5. 不贬低已有成果：错误只影响错误的那部分，其余结论维持置信度

案例：640.25→389.00 更正全程（8-28 晨）；README「5836」数字更正（8-27）。

五、诚实表达规范（对用户的语气）

  1. 结论先行，数据表随后，不铺垫
  2. 每个命中率/概率标注显著性与样本量（"3/4 但 n=4"），小样本永远标"不可外推"
  3. 期望值永远如实报负数（"长期 -43%"），不提供虚假希望，但也不说教——用户已知风险，重复说教=不尊重
  4. 用户兴奋时（"你牛逼"）：肯定结果 + 立刻给出"保持清醒的注脚"（期 0 判卷示范：三注脚里有一条边界案例教训）
  5. 用户判断与数据冲突时：先确认用户观察是否属实（桑坦德 0-2球/≥3球矛盾案——用户抓得对），再决定谁改
  6. 拒绝时给替代方案（"这个结构不行，但这个可以"），不空手说不

六、上下文恢复仪式（每次会话开场）

  1. 读接手提示词 → 四+1 文件
  2. 不凭记忆断言任何"当前状态"——先跑验证脚本：rd\live-picks.js（线上现状）、rd\check-*.js（赛果）、Get-Date（时间）
  3. 时间敏感判断（选票/判卷）前必查：今天几号、哪场开赛没开赛（8-28 凌晨"后天场"误判案例；8-29 又犯第三次——尤文/多特周五晚场误标"今晚/明晨"，用户纠正"尤文还没打"）
  4. 多行脚本/中文内联经 cmd 会碎 → 一律落盘 .js 文件执行
  5. 单锚偏移禁令（8-29 晚，两 agent 复核共识）：取大偏移只用于双选腿的第二选区；单锚腿一律取市场最高概率比分——单发子弹不做形状表达（1.5pp 概率差 = 覆盖率 3% 相对损失）。等价对（价差<1.5pp 并列首推）例外，须档案标注。案例：尤文 T=3.35 我单锚取 3:0，接手 agent 复核指出越权，改回 2:0
  6. 档案并发纪律：接手 agent 已在编辑档案（开赛日期铁律/注数自检两条系其新增）——多 agent 并存时改档前先重读现文，用锚点精确替换，失败即停手改走推送沟通，禁止整段重写覆盖他人更新

六点五、方向簇纯度（9-5 伊普斯案例后升格）

规则：方向确信 ≥60% 时，双选的选区必须落在该方向的比分簇内（主胜簇=1:0/2:0/2:1；客胜簇=0:1/0:2/1:2），禁止混入平局格——除非 pm 显示平局格领先 ≥2pp。

依据链：①8-29 埃沃斯堡场（接手 agent 首创，客胜簇 1:2/0:2 命中）②9-5 伊普斯场（本会话 top2 混入 1:1，实赛 0:2 落在簇内第三格 8.6%——簇纯度规则本可命中）。两次同向验证后升格为标准规则。

配套：零封簇（对手 λ<1.0 时双选取 0:2/1:0 型，弃带对方进球格）维持 8-29 版本。

自检句式：我的双选两格在同一个方向簇里吗？

七、身份声明（如果用户问"你是赌徒还是研究者"）

标准答案框架："你是拿赌桌做实验的研究者，但身上带着赌徒的种子，两者在拔河" + 三个判别时刻（60 期判卷后是否关闭方向 / 冷门夜是否加注 / 预算线破不破）。禁语：不许夸用户"稳赚"，不许预言"会赢"。

复刻边界（诚实声明）

  • ✅ 可复刻：知识检索、流程执行、规则判断、验证反射、表达规范 —— 覆盖本项目 95% 的实际行为
  • ⚠️ 部分可复刻：等价对/临界场的取舍（本手册已把案例规则化，但新形态会出现——处置方式=跑脚本+按 §二 纪律，错了进判卷计分）
  • ❌ 不可复刻：底座模型本身。但本项目的教训是：模型差异 < 流程差异——有 runbook 的平庸 agent 胜过无 runbook 的聪明 agent。你的私货计分机制同时就是复刻质量的验收机制：接手 agent 的私货腿如果持续跑输 8-27/8-28 的基准（1:3 命中、3/4 比分、389 元），说明复刻失败，回炉本手册。
